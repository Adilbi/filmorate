# 🎬 Filmorate

**Filmorate** (от англ. *film* — «фильм» и *rate* — «оценивать») — бэкенд сервиса для работы с фильмами и пользователями.
Пользователи могут добавлять друг друга в друзья, ставить фильмам лайки и получать топ популярных фильмов.

Данные пока хранятся в памяти, входящие запросы проверяются валидацией, ошибки возвращаются с понятными HTTP-кодами.
Дальше по плану — хранение в базе данных.

## 🏗 Архитектура

Приложение разделено на три слоя, каждый отвечает за своё:

```
Controller  →  Service  →  Storage
  HTTP          логика       хранение
```

| Слой | Классы | Ответственность |
|---|---|---|
| **Controller** | `FilmController`, `UserController` | принимает HTTP-запросы и отдаёт ответы, логики не содержит |
| **Service** | `FilmService`, `UserService` | валидация, друзья, лайки, популярные фильмы, логирование |
| **Storage** | интерфейсы `FilmStorage`, `UserStorage` и реализации `InMemoryFilmStorage`, `InMemoryUserStorage` | хранение, поиск, обновление и удаление объектов |

Зависимости внедряются Spring через конструкторы. Сервисы работают с **интерфейсами** хранилищ, поэтому хранение в памяти можно заменить на базу данных, не трогая бизнес-логику.

## 📡 API

### Фильмы — `/films`

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/films` | Добавить фильм |
| `PUT` | `/films` | Обновить фильм (по `id` в теле) |
| `GET` | `/films` | Получить все фильмы |
| `GET` | `/films/{id}` | Получить фильм по `id` |
| `PUT` | `/films/{id}/like/{userId}` | Пользователь ставит лайк фильму |
| `DELETE` | `/films/{id}/like/{userId}` | Пользователь убирает лайк |
| `GET` | `/films/popular?count={count}` | Топ `count` фильмов по количеству лайков (по умолчанию 10) |

<details>
<summary>Пример запроса</summary>

```http
POST /films
Content-Type: application/json

{
  "name": "Бен 10: Секрет Омнитрикса",
  "description": "Полнометражный мультфильм",
  "releaseDate": "2009-08-09",
  "duration": 69
}
```

```json
{
  "id": 1,
  "name": "Бен 10: Секрет Омнитрикса",
  "description": "Полнометражный мультфильм",
  "releaseDate": "2009-08-09",
  "duration": 69,
  "likes": []
}
```
</details>

### Пользователи — `/users`

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/users` | Создать пользователя |
| `PUT` | `/users` | Обновить пользователя (по `id` в теле) |
| `GET` | `/users` | Получить всех пользователей |
| `GET` | `/users/{id}` | Получить пользователя по `id` |
| `PUT` | `/users/{id}/friends/{friendId}` | Добавить в друзья |
| `DELETE` | `/users/{id}/friends/{friendId}` | Удалить из друзей |
| `GET` | `/users/{id}/friends` | Список друзей пользователя |
| `GET` | `/users/{id}/friends/common/{otherId}` | Общие друзья двух пользователей |

<details>
<summary>Пример запроса</summary>

```http
POST /users
Content-Type: application/json

{
  "email": "user@mail.ru",
  "login": "ben10",
  "birthday": "2000-01-01"
}
```

```json
{
  "id": 1,
  "email": "user@mail.ru",
  "login": "ben10",
  "name": "ben10",
  "birthday": "2000-01-01",
  "friends": []
}
```
Имя не передано, поэтому вместо него подставлен логин.
</details>

### Правила работы друзей и лайков

- Дружба **взаимная**: если пользователь 1 добавил в друзья пользователя 2, то и у пользователя 2 в друзьях появляется пользователь 1. При удалении связь пропадает у обоих.
- Один пользователь может поставить фильму **только один** лайк — повторный не учитывается.
- Друзья и лайки **не теряются** при обновлении пользователя или фильма через `PUT`, даже если клиент не передал их в теле запроса.
- Популярные фильмы сортируются по количеству лайков по убыванию.

## ✅ Валидация

### Фильм

| Поле | Правило |
|---|---|
| `name` | не может быть пустым |
| `description` | не длиннее 200 символов |
| `releaseDate` | не раньше 28 декабря 1895 года (первый киносеанс) |
| `duration` | положительное число (минуты) |

### Пользователь

| Поле | Правило |
|---|---|
| `email` | не может быть пустым, должен содержать `@` |
| `login` | не может быть пустым и содержать пробелы |
| `name` | может быть пустым — тогда используется `login` |
| `birthday` | не может быть в будущем |

## ⚠️ Ошибки

Ошибки обрабатываются централизованно (`@RestControllerAdvice`) и возвращаются в едином формате:

```json
{ "message": "Фильм с id = 99 не найден" }
```

| Ситуация | HTTP-код |
|---|---|
| Данные не прошли валидацию | `400 Bad Request` |
| Некорректный запрос: битый JSON, текст вместо числа в пути или параметре | `400 Bad Request` |
| Фильм или пользователь с указанным `id` не найден | `404 Not Found` |
| Любая другая непредвиденная ошибка | `500 Internal Server Error` |

При ошибке `500` клиент получает только общее сообщение, а подробности и стектрейс пишутся в лог.
Создание и обновление сущностей, а также причины ошибок тоже логируются.
